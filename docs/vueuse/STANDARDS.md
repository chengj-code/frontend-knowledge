# 学习文档规范

> 本文件定义了 learning-docs 文件夹的组织规范和编写约定。
> **每次开始新阶段学习前，请先阅读本文档。**

---

## 一、文件夹结构规范

### 1.1 基本结构

```
learning-docs/
├── STANDARDS.md          # 本文件，规范文档（优先阅读）
├── PROGRESS.md           # 学习进度追踪（每完成一个阶段更新）
├── README.md             # 总览和说明
├── stage-N/              # 阶段目录
│   ├── README.md         # 阶段总览（必须）
│   └── hook-name.md      # 单个 hook 详细文档（内容多时拆分）
```

### 1.2 命名规则

| 类型 | 命名格式 | 示例 |
|------|---------|------|
| 阶段目录 | `stage-{N}` | `stage-1`、`stage-2` |
| 阶段总览 | `stage-N/README.md` | `stage-1/README.md` |
| 单 hook 文档 | `stage-N/{hookName}.md` | `stage-2/useToggle.md` |

**命名原则：**
- 目录名使用小写 + 短横线（kebab-case）
- hook 文档名与源码目录名保持一致（camelCase）
- 文件名不加序号前缀，通过文件夹层级体现顺序

### 1.3 何时拆分单 hook 文档

| 情况 | 处理方式 |
|------|---------|
| 阶段内 hook 数量 ≤ 3 且每个代码量 < 100 行 | 全部写在 `README.md` 中 |
| 阶段内 hook 代码量 ≥ 200 行 | 该 hook 拆分为独立文档 |
| 阶段内 hook 涉及复杂设计模式（状态机、Proxy 等） | 该 hook 拆分为独立文档 |
| 阶段内 hook 数量 ≥ 5 | 每个 hook 拆分为独立文档 |

**判断示例：**
- 阶段 1（4 个 hook，每个 < 80 行）→ 写在 README.md
- 阶段 2（2 个 hook，每个 < 80 行）→ 写在 README.md
- 阶段 5（10 个 hook）→ 每个 hook 拆分为独立文档
- 阶段 6（useStorage 323 行）→ 拆分为独立文档

## 二、阶段总览文档（README.md）规范

### 2.1 必须包含的章节

```markdown
# 阶段 N：{阶段名称}（预计 X-X 天）

> 一句话概括本阶段的核心目标

## 学习清单           # 表格：序号、文件路径、行数、核心知识点
## 阅读顺序           # 用 → 连接的阅读顺序
## 学习目标           # checkbox 列表
## 关键代码解读       # 精选 1-3 个关键代码片段（可选）
## 练习               # 2-5 个练习任务
## 笔记               # 留白区域，记录学习笔记
```

### 2.2 学习清单表格格式

```markdown
| 序号 | 文件 | 行数 | 核心知识点 |
|------|------|------|-----------|
| 1 | `packages/shared/useToggle/index.ts` | 54 | 策略模式、条件返回类型 |
```

**字段说明：**
- **文件**：相对于项目根目录的路径，用反引号包裹
- **行数**：大致行数即可，用于评估复杂度
- **核心知识点**：2-4 个关键词，用顿号分隔

### 2.3 学习目标格式

```markdown
## 学习目标

- [ ] 理解 xxx 的核心概念
- [ ] 掌握 xxx 的用法
- [ ] 能独立实现 xxx
```

**动词选择：**
- **理解**：知道是什么、为什么
- **掌握**：能解释给别人听、能写出代码
- **精读**：逐行读懂源码实现

### 2.4 阅读顺序格式

用代码块包裹，用 `→` 连接：

```markdown
## 阅读顺序

\```
useToggle → useCounter
\```
```

如果是拆分了独立文档的阶段，阅读顺序中标注**重点精读**的文件：

```markdown
## 阅读顺序

\```
useMounted → useSupported → _configurable.ts
  → useEventListener（重点精读，建议花 1 天）
  → useMouse → useWindowSize → useFullscreen
\```
```

## 三、单 Hook 文档规范

### 3.1 必须包含的章节

```markdown
# {hookName}

> 一句话说明这个 hook 的用途

## 基本信息           # 文件路径、行数、所属包
## 源码结构           # 导出函数、类型定义、依赖关系
## 设计模式           # 使用了哪些设计模式
## 核心实现解读       # 分段解读关键代码
## TypeScript 技巧    # 泛型、重载、条件类型等
## SSR 兼容           # 如何处理 SSR（如适用）
## 关联 hook          # 依赖的和被依赖的 hook
## 练习               # 动手实践任务
## 笔记               # 学习笔记
```

### 3.2 基本信息格式

```markdown
## 基本信息

| 属性 | 值 |
|------|-----|
| 文件路径 | `packages/shared/useToggle/index.ts` |
| 代码行数 | 54 行 |
| 所属包 | `@vueuse/shared` |
| 依赖工具 | `shallowRef`、`isRef`、`toValue` |
| 设计模式 | 策略模式 |
```

### 3.3 核心实现解读格式

按功能模块分段，每段包含：
1. **代码片段**（从源码中摘取关键部分）
2. **逐行解释**（用注释或文字说明）
3. **设计意图**（为什么这样写）

```markdown
## 核心实现解读

### 1. 参数解析

\```ts
// 源码片段
\```

**解释：**
- 第 X 行：做了什么，为什么这样做
- 第 Y 行：处理了什么边界情况

**设计意图：** 这里使用 xxx 模式是为了...
```

### 3.4 TypeScript 技巧格式

```markdown
## TypeScript 技巧

### 函数重载

\```ts
// 重载签名示例
\```

**作用：** 根据参数类型返回不同结构
**关键：** 重载顺序很重要，更具体的签名要放在前面
```

## 四、学习流程规范

### 4.1 每次学习的标准流程

```
1. 阅读 STANDARDS.md（本文件）—— 确认规范
2. 打开 PROGRESS.md —— 确认当前进度
3. 打开当前阶段的 stage-N/README.md —— 查看学习清单
4. 按阅读顺序逐个阅读源码
5. 在对应文档中记录笔记
6. 完成练习
7. 更新 PROGRESS.md —— 标记完成状态
```

### 4.2 源码阅读规范

**阅读顺序原则：**
- 先读类型定义，再读实现
- 先读主函数签名，再读函数体
- 先读依赖的工具函数，再读使用它们的 hook

**标注约定：**
- `⭐` 标记：重点/难点，需要反复阅读
- `💡` 标记：巧妙的设计，值得学习
- `⚠️` 标记：容易出错的点
- `🔗` 标记：与其他 hook 的关联

### 4.3 笔记记录规范

**必须记录的内容：**
- 核心收获（用自己的话总结）
- 不理解的地方（标记为 `❓` 待解决）
- 与已有知识的关联

**可选记录的内容：**
- 关键代码片段的个人理解
- 练习的实现思路和结果
- 改进建议或替代方案

**笔记格式：**

```markdown
## 笔记

### 核心收获
- 收获 1
- 收获 2

### 疑问
- ❓ 问题 1
- ❓ 问题 2

### 练习记录
\```
练习 1 的实现代码或思路
\```
```

## 五、进度更新规范

### 5.1 完成一个阶段后的操作

1. 在阶段 README.md 中勾选所有学习目标
2. 在阶段 README.md 的笔记区记录总结
3. 更新 `PROGRESS.md`：
   - 将阶段状态从 `⏳ 进行中` 改为 `✅ 已完成`
   - 填写完成日期
   - 填写核心收获
   - 更新总体进度百分比
   - 更新"下一步计划"
4. 如果有拆分的独立 hook 文档，确认所有文档都已完成笔记

### 5.2 开始一个新阶段前的操作

1. 更新 `PROGRESS.md`：
   - 将新阶段状态从 `⏸️ 未开始` 改为 `⏳ 进行中`
   - 填写开始日期
   - 更新"下一步计划"
2. 阅读新阶段的 README.md，了解学习内容
3. 如果阶段内容较多，提前规划是否需要拆分独立文档

### 5.3 PROGRESS.md 更新模板

```markdown
## 阶段 N：{阶段名称} ✅

**完成日期：** YYYY-MM-DD

### 关键收获

1. 收获 1
2. 收获 2
3. 收获 3

### 设计模式掌握

| 模式 | 掌握程度 | 笔记 |
|------|---------|------|
| xxx | ✅ 掌握 | 简要说明 |
```

## 六、文档质量检查清单

完成一个阶段后，用以下清单自检：

- [ ] README.md 包含所有必须章节
- [ ] 学习清单中的文件路径准确
- [ ] 学习目标已全部勾选
- [ ] 关键代码解读使用了正确的代码块格式
- [ ] 笔记区记录了核心收获和疑问
- [ ] 练习已完成（或记录了未完成的原因）
- [ ] PROGRESS.md 已更新
- [ ] 如有拆分文档，所有 hook 文档已完成

## 七、阶段内容复杂度参考

用于判断是否需要拆分独立文档：

| 阶段 | hook 数量 | 平均代码量 | 拆分建议 |
|------|----------|-----------|---------|
| 阶段 1 | 4 | ~15 行 | 不拆分 |
| 阶段 2 | 2 | ~60 行 | 不拆分 |
| 阶段 3 | 7 | ~60 行 | 可选（useTimeoutFn/useIntervalFn 可拆分） |
| 阶段 4 | 8 | ~35 行 | 可选（filters.ts 可拆分） |
| 阶段 5 | 10 | ~110 行 | **建议拆分**（useEventListener 必须拆分） |
| 阶段 6 | 5 | ~290 行 | **建议拆分**（useStorage/useWebSocket 必须拆分） |
| 阶段 7 | 4 | ~350 行 | **建议拆分**（until/useFetch 必须拆分） |
